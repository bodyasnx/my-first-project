# Тестування лендінгу VXE R1 Pro Max

Практичне заняття № 25 «Тестування, DevTools, виправлення помилок».

## Середовище

| Параметр | Значення |
|---|---|
| Сторінка | `http://127.0.0.1:5500/index.html` (Live Server) |
| Сервер API | Node.js + Express, `http://localhost:3000` |
| Браузери | Google Chrome, Mozilla Firefox |
| Розміри екрана | iPhone SE 375 × 667, iPad Mini 768 × 1024, ноутбук 1280 × 800, десктоп 1920 × 1080 |
| Інструменти | Chrome DevTools: Console, Issues, Network, Device Toolbar |

## Журнал дефектів

| ID | Важливість | Було | Причина | Виправлення | Коміт |
|---|---|---|---|---|---|
| D-1 | Висока | Вибрана «Тема звернення» не надходить на сервер | У обробнику форми не читалося значення `#topic`, його не було в об'єкті `data` | Додано `const topic = document.querySelector('#topic').value` і `topic` в `data` | «Виправив: тема звернення тепер надсилається на сервер» |
| D-2 | Середня | Після прокручування чи перезавантаження з `#contacts` підсвічено «Головна» | Скрипт підсвічував перший пункт при завантаженні й змінював підсвічування лише за кліком | `IntersectionObserver` стежить за секціями й підсвічує пункт тієї, що посередині екрана | «Виправив: меню підсвічує секцію, яка зараз на екрані» |
| D-3 | Низька | Повідомлення «Не вдалося завантажити…» стоїть вузьким стовпчиком у першій колонці | Повідомлення — звичайний елемент сітки на 3–4 колонки | Класи `col-span-full text-center` для повідомлень завантаження й помилки | «Виправив вирівнювання повідомлень завантаження в сітках» |
| D-4 | Середня | У футері: «форма поки що нікуди не надсилає дані» | Текст не оновили після практичної 22, коли форма почала надсилати дані на сервер | Новий текст: «дані форми надходять на локальний сервер Node.js» | «Виправив застарілий текст про форму у футері» |
| D-5 | Низька | DevTools Issues: «An element doesn't have an autocomplete attribute» (3 поля) | Атрибут `autocomplete` не додали при створенні форми | `autocomplete="name"`, `"email"`, `"tel"` | «Додав autocomplete до полів форми» |
| D-6 | Низька | DevTools Issues: «Lazy-loaded images should have explicit dimensions» (6 фото) | `width: auto; height: auto` у `.gallery img` скасовували атрибути `width`/`height` | `height: 100%`, `width: auto`, `object-fit: contain`; місце резервується до завантаження (перевірено вимірюванням) | «Виправив: атрибути розмірів зображень галереї більше не скасовуються CSS» |

Примітка до D-6: попередження в Issues лишається, бо перевірка Chrome вважає явними лише фіксовані розміри й не враховує висоту у відсотках. Вимірювання показало, що незавантажені фото вже мають розмір (наприклад, 113 × 192 і 316 × 192), тобто зсуву макета немає.

## Знайдено, але не є дефектом сайту

| Спостереження | Висновок |
|---|---|
| Console / Issues: «Content Security Policy blocks the use of eval» | Помилку викликає розширення браузера: в інкогніто її немає |
| Network: запити `intro-offer.tsx`, `jsx-runtime`, `webcomponents-bundle` та ін. (~470 кБ) | Ресурси розширень браузера, не сайту; власні ресурси сторінки ~100 кБ |
| Network: `ws` зі статусом 101 | WebSocket Live Server для автооновлення, лише під час розробки |
| На вузьких екранах миша майже повністю закриває напис «R1» | Косметичне: напис декоративний (`aria-hidden`), без виправлення |
| На GitHub Pages «Мої проєкти» й форма звертаються до `localhost:3000` | Відоме обмеження архітектури: сервер працює лише локально |

## Результати перевірок DevTools

- **Console:** помилок і попереджень сайту немає.
- **Network:** усі запити 200, помилок 404/500 немає; найповільніший ресурс — шрифт (76 мс), подія `Load` — 198 мс; фото галереї завантажуються лише при прокручуванні (`loading="lazy"`).
- **Режим пристроїв:** горизонтальної прокрутки немає, верстка коректна на всіх розмірах.
- **Firefox:** відображення й поведінка збігаються з Chrome.
